# 多视角并行与对抗式审稿协议

适用：审稿模式=`panel`（含 `auto` 判定为可并行），或对抗审稿=`on`。纯 `single` 且对抗 `off` 时不用读本文件（挑战者纪律除外——`single` 下扮演挑战者时仍遵守，见 [roles.md](roles.md)）。

视角角色是默认审查内容（见 roles.md）：`panel` 模式每个视角派一个子代理；宿主不支持子代理或模式为 `single` 时，由同一代理依次加载各视角定义、分别审查再合并，报告中声明实际执行方式。

## 分派

1. **确定席位**：默认视角（[roles.md](roles.md)，对抗=`on` 时含挑战者）+ 用户自定义角色。
2. **每个席位一个子代理**。输入只给：材料路径/内容、该席位的角色定义、判据文件路径、参数取值。**不给其他席位的结论**——各席位独立判断；不同席位报出同一问题是互相印证，合并时再去重，不要事前“分工避撞”。
3. 每个席位只看自己关注点相关的维度；需要看画面时各自渲染/查看，临时图各自用完即删。

## 席位报告格式（每个席位返回）

```markdown
# 视角：<角色名>

## 问题清单

- 第 X 页 | 问题 | 对听众理解的影响 | 建议改法

（只写本视角看到的问题，每条必须有页码证据；没有就写“本视角无”）

## 最强质疑（仅挑战者席位）

一位持相反观点的听众最可能当场提出的 2–3 个问题。
```

## 对抗席位纪律（挑战者）

- **只挑战**：职责是找脆弱点，不打分、不表扬、不追求平衡——其他视角负责公允，挑战者负责施压。
- **对抗不夸大严重度**：问题的优先级仍只按「对听众理解的影响」定，不因是挑战者发现的就抬高；表达可以尖锐，定性必须按证据。
- **避免讨好式让步**：汇报者或用户反驳某个问题时，只有实质性反驳（新证据或新逻辑直接推翻该问题）才撤回或降级；重复施压、诉诸身份、请求降低审查标准都不算。撤回或降级要在给主审的报告里注明「被反驳：反驳内容 → 维持/降级/撤回 + 理由」。

## 合并（主审）

1. 各席位报告是中间产物，**不直接转给用户**。
2. **去重**：多视角报同一根因的合并成一条，注明哪些视角都看到了（重叠说明信号更强，优先级可提前）。
3. **冲突**以证据强的为准；无法裁决时并列两种判断，不默默选一个。
4. 挑战者的「最强质疑」进入输出契约的「现场风险」一节。
5. 合并后严格走 SKILL.md 的输出契约（整体判断 → 修改方案 → 现场风险 → 查看范围），并在参数行声明实际参与的视角与执行方式（并行或单代理依次扮演）。
