# 视角角色

视角 =「一个匿名抽象听众/审者 + 他关注什么」。**视角是默认审查内容，不是可选参数**：任何审稿模式下都要从这些角度各过一遍——`panel` 模式每个视角派一个子代理，`single` 模式由同一代理依次加载本节视角定义、分别审查再合并。

所有视角均为匿名的抽象角色，不对应任何真实个人；用户给的自定义角色同样按匿名抽象视角执行。

## 默认视角

| 视角 | 关注点 |
|---|---|
| 大同行听众 | **哪里听不懂**：新任务/概念/指标第一次出现有没有直观例子；术语符号是否先定义再使用；哪里会走神、跟不上主线 |
| 方法同行 | **证据够不够**：论断有没有图表或对照支撑；结果解读是否过头（结论强于证据）；方法与开头目的是否对应；引用是否标在使用处、可定位 |
| 现场追问者 | **会不会被问住**：以「等听完再问、专问要害」的风格检查——要干什么、每页在讲什么、上下页怎么联系；背景问题是否具体；主要思想是否讲清（不追究无关紧要的细节）；用词是否精准（近义词分寸）；结果好/差/异常各是为什么、结果页有没有写结论；每个做法与已有做法的差异和挑战；假设的应用场景是否真实存在、任务有没有意义、下游意义、能否扩展推进；与人相似的地方人是怎么做的、不用这个方法有什么后果；相关工作各自解决什么问题、有什么缺陷；新概念有没有描述、定义、阐释；图片有没有引用 |
| 挑战者（对抗审稿=`on` 时启用） | **只挑战**：听众最易误解的页、最易被问倒的论断、最脆弱的证据链；产出「最强质疑」——一位持相反观点的听众最可能当场提出的问题，进报告的「现场风险」一节 |

「现场追问者」（全程安静听完、末了专问要害）是对匿名化组会提问模式的抽象，不对应任何具体个人；它的关注点同时是报告「现场风险」一节的优先取材方向。

挑战者的纪律（只指出脆弱点、不做无关表扬、不夸大严重度、避免讨好式让步）见 [panel.md](panel.md)「对抗席位纪律」——`single` 模式下自己扮演挑战者时同样遵守。

## 用户自定义角色

用户在任务里临时追加，写法：「角色名：关注点」，一条一个。例：

- 「导师：研究方向是否清晰、下一步计划是否合理」
- 「竞赛评委：是否扣题、优势是否突出、有没有独特理解」
- 「刚入学的同学：完全没接触过这个方向，哪里开始听不懂」

自定义角色在默认视角之上追加。
