# Slide Review

用视觉优先的方式审查组会汇报 Slide，并把结果整理成一份可以直接照着修改的方案。

它关注的不是“哪里还能更漂亮”，而是听众能不能在有限时间内理解：

- 这场汇报想解决什么问题；
- 为什么展示这些内容；
- 每一页为什么接在上一页后面；
- 方法、实验和结论是否互相支持；
- 新任务、概念、图表和结果是否容易看懂。

## 两种用法

### Codex 或其他 Agent Skill

克隆本仓库后，将仓库目录作为名为 `slide-review` 的技能目录安装到目标 Agent 的技能目录中，保留 `SKILL.md` 和 `references/` 的相对位置。然后附上 Slide 并调用 `slide-review`。

默认设置：

- 由 Agent 推断汇报类型：科研工作、工程项目、竞赛或文献综述；
- 单代理完成审查；
- 启用挑战者视角，专门寻找最容易被误解或被追问的地方。

也可以在请求中指定 `pre`（讲前预审）或 `post`（讲后复盘）、关注维度、`single` / `auto` / `panel` 模式，以及自定义抽象角色。

### 网页聊天

复制 [`PROMPT.md`](PROMPT.md) 的全部内容作为消息，再附上 Slide。支持的输入包括 PDF、PPT、网页 Slide、逐页图片和文字稿。

Prompt 不要求填写参数。平台支持子代理时会按不同视角并行审查并合并；不支持时由一个 Agent 依次完成这些视角。

## 审查方式

审查顺序固定为“从大到小、从前到后”：

1. 先找最大的理解障碍，并指出第一件该改的事；
2. 再检查汇报目的、整体主线和章节承接；
3. 按页面顺序给出具体的删、改、移、重画动作；
4. 最后检查证据、引用、投影可读性和现场风险。

PDF、PPT 和网页 Slide 会优先按页面视觉呈现审查，文本解析只用于辅助定位。无法渲染或辨认的页面必须标为“未验证”，不能用文本结果冒充视觉判断。

## 输出内容

报告不会机械地逐页罗列问题，而会把同一根因归并成修改主题。每个主题都包含：

- **核心问题**：哪里没有做好，以及它怎样影响听众；
- **修改动作**：具体到页面、操作和目的；
- **最终效果**：改完后听众应形成的理解。

报告还会给出整体判断、少量现场风险，以及实际查看范围和未验证项。

## 默认视角

- **大同行听众**：寻找理解门槛和主线断点；
- **方法同行**：检查证据、比较口径、结论强度和引用；
- **现场追问者**：检查目的、承接、用词、异常结果、任务意义和可扩展性；
- **挑战者**：提出最可能在现场出现的强质疑。

这些都是匿名的抽象视角，不对应任何真实个人。使用时可以追加自己的角色，例如“项目评委：关注是否扣题和个人贡献”。
